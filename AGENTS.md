# AGENTS.md — `hivemind-usenet`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

An experimental HiveMind transport that carries the protocol over Usenet
instead of a live WebSocket: PGP-encrypted, hSub-addressed articles posted to
`alt.anonymous.messages` and reassembled on poll. It is high-latency and
store-and-forward by design, not a low-latency audio channel. Part of the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core); the client
library is
[hivemind-bus-client](https://github.com/JarbasHiveMind/hivemind-bus-client).
The package ships three surfaces: `UsenetCarrier` (the framing/crypto layer,
testable without a live NNTP connection), `UsenetWormhole` (a `NetworkProtocol`
registered under `hivemind.network.protocol` that tunnels full `HiveMessage`
objects hub-side), and `UsenetBridge` (a natural-language gateway, the closest
analogue to the org's chat-platform bridges). `HiveMindUsenetClient` is the
satellite-side counterpart, mirroring the HTTP/WS client API.

## Layout / build / test

- Package module: `hivemind_usenet/`. Tests live in `tests/` (unit tests at
  the top level, `tests/e2e/` for the in-process hivescope harness — check
  before adding, do not create a second test directory).
- Python is capped `>=3.10,<3.13`: the PGP carrier crypto (`remailers` →
  PGPy) imports the stdlib `imghdr` module, removed in 3.13. Do not raise the
  ceiling without first replacing that dependency chain.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests/ -q`. `tests/e2e/`
  uses `hivescope` to run a real hivemind-core master and a real
  `HiveMindSlaveProtocol` against an in-memory fake NNTP server (`FakeNNTPServer`
  in `tests/e2e/usenet_link.py`) — the HiveMind handshake and PGP crypto are
  real, only the NNTP socket is faked, so it does catch real handshake and
  carrier-framing breaks. It does not exercise a live news server.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is
  a bug to FIX at the source, not to work around with a pin downgrade.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- **`UsenetBridge` must bound its handshake.** `_get_hm_client()` in
  `hivemind_usenet/bridge.py` builds a `HiveMessageBusClient` and calls
  `.connect()` with no arguments. The `hivemind_bus_client` floor pin here is
  `>=0.9.2a1`, whose `connect()` default for `handshake_max_retries` is
  `None` — retry forever. Against a stalled or unreachable hub this hangs the
  bridge's lazy client-init path indefinitely instead of failing fast. Any
  change to `_get_hm_client()` must add an explicit finite
  `handshake_max_retries` (exposed as a constructor parameter), and the
  `hivemind_bus_client` floor should be raised to `>=1.0.13a1` or later as
  part of that fix — do this as a standing requirement, not something already
  in place.
- **Composition, not inheritance, for the bus client.** `_get_hm_client()`
  builds the `HiveMessageBusClient` lazily and connects it exactly once on
  first use, then caches it on `self._hm_client`. Never add a second
  `connect()` call on the cached instance and never call `run_forever()` on
  it — nothing in this bridge currently does; keep it that way.
- **`UsenetWormhole` and `HiveMindUsenetClient` do not use
  `HiveMessageBusClient` at all.** They drive `HiveMindSlaveProtocol` /
  `HiveMindClientConnection` directly, with the carrier's `send`/`poll`
  standing in for the socket. `connect()` on `HiveMindUsenetClient` only
  starts the handshake and returns — it is asynchronous by construction, not
  an unbounded-retry bug, because the actual HELLO/HANDSHAKE round trip
  happens later on the poll thread (`run()`). `wait_for_handshake(timeout=...)`
  is the caller's tool for bounding that wait; do not make `connect()` itself
  block.
- **ACL enforcement lives on the hub, not here.** A freshly registered
  HiveMind client (over the wormhole or the satellite client) is denied every
  message type until an admin runs `hivemind-core allow-msg <type>
  <client_id>`. Neither `UsenetWormhole` nor `HiveMindUsenetClient` has a way
  to grant itself permissions, and none should be added — a message silently
  dropped by the hub's ACL is the hub doing its job. `UsenetBridge`'s
  `allowed_senders` is a separate, bridge-side filter over which Usenet peers
  may originate traffic; it is not a substitute for hub-side ACLs.
- **Rejected credentials must fail fast, not poll forever.** Once
  `handshake_max_retries` is bounded per the rule above, a bad access
  key/password must surface as a clean failure. Do not add retry/backoff
  logic on top of `connect()` or the poll loop that defeats a bounded retry
  count.
- **Forward upstream responses verbatim.** `UsenetBridge._process_item()`
  passes `client.ask(...)`'s return value straight to the reply callback; do
  not reformat, truncate, or add bridge-specific decoration to hub-authored
  text. The fixed "Error processing request." fallback is bridge-authored by
  design, for the case where the hub call itself raised.
- **Thread/loop bridging.** Every surface here (`UsenetBridge`,
  `UsenetWormhole`, `HiveMindUsenetClient`) is a `threading.Thread` running a
  synchronous poll loop, not asyncio — there is no `run_coroutine_threadsafe`
  bridging in this repo and none should be needed. `UsenetBridge` additionally
  runs one `_SessionQueue` worker thread per peer session (BRIDGE-1 FIFO);
  new inbound-message paths must enqueue onto the correct per-session queue
  rather than calling the HiveMind client directly from the poll thread, or
  the FIFO ordering guarantee breaks.
- **Secret-naming symmetry is load-bearing and confusing — do not "simplify"
  it.** `client.py`'s docstring works through why `my_secret`/`hub_secret` on
  `HiveMindUsenetClient` map to `peer_secret`/`my_secret` on `UsenetWormhole`
  in swapped order. Read that docstring before touching either side; a naming
  refactor that looks obviously correct in one file can silently invert the
  hSub addressing in the other.
